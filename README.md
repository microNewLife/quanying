# 犬影村管理平台

管理端沿用 Vue，支持浏览器和 Electron；小程序使用 Supabase。人员资料存入 `people`，一人多项认证存入 `certifications`。

## 从源码开始

需要 Node.js 22.18+（推荐 Node.js 24 LTS）、npm；小程序需微信开发者工具。

```sh
git clone https://github.com/microNewLife/quanying.git
cd quanying
cp admin/.env.example admin/.env
cp miniprogram/env.example.js miniprogram/env.js
# 填写自己的 Supabase URL 和公开客户端密钥后：
cd admin
npm ci
npm test
npm run dev
```

- `admin/`：Vue 管理端、Electron 桌面壳、测试及维护脚本。
- `miniprogram/`：微信小程序；在该目录运行 `npm install`，再按其 README 构建 npm。
- `supabase/`：数据库迁移和登录函数；`schema.sql` 为初始数据库结构。
- `local-data/`：仅本机保留的两份名单 Excel 和 `teachers_data.json`，整个目录不提交。克隆仓库不包含此目录。

`.env`、小程序 `env.js`、个人开发工具设置、数据库备份、依赖目录、构建结果及安装包均已忽略。不要把服务端管理密钥放入客户端配置。需要真实名单的桌面冒烟测试和历史迁移演练脚本，从 `local-data/` 读取名单；运行前由维护者自行放入文件。普通测试使用合成数据，不依赖名单。

`admin/scripts/*-live.mjs` 是针对原项目的维护工具，可能读取或修改线上数据库，并非启动步骤；使用前核对目标项目与备份。

## 启用新版

1. 先备份线上数据库及 Storage 图片。新版迁移保留旧 `teachers` 表，但这不能替代完整备份。
2. 已有项目按顺序执行 [人员与导入迁移](supabase/migrations/202609140001_people_import.sql) 和 [旧版读取兼容迁移](supabase/migrations/202609140002_legacy_read_compatibility.sql)，不要重跑根目录 `schema.sql`。全新项目先执行 `schema.sql`，再执行迁移。每份迁移仅执行一次；生产切换应将两份脚本的内容合并至同一个事务中执行，避免中间状态。
3. 在 Supabase Authentication 中确认管理员账号存在。使用 SQL Editor 执行下面的语句，将示例 UUID 换成该账号的实际 ID。不能用邮箱或客户端自行赋权。

   ```sql
   insert into public.admin_users(user_id)
   values ('替换为管理员用户UUID');
   ```

4. `admin/.env` 配置 `VITE_SUPABASE_URL` 与 `VITE_SUPABASE_PUBLISH_KEY`（或 `VITE_SUPABASE_ANON_KEY`）。只使用 publishable/anon 密钥。配置在构建时写入客户端，绝不放 service_role 或 secret key。小程序的 `miniprogram/env.js` 配置对应项目。
5. 先在测试项目验收，再部署数据库与新版后台。第二份迁移将旧 `teachers` 表保留为 `teachers_legacy_backup`，并建立同名只读兼容视图，旧版小程序及旧分享链接可继续读取已公开数据。新版小程序可随后更新为一人多认证界面。旧版后台不再具备写入名单权限，应改用新版后台。

```sh
cd admin
npm ci
npm test
npm run desktop
```

浏览器开发使用 `npm run dev`。本机应用目录包用 `npm run pack`；macOS 安装盘用 `npm run dist:mac`；Windows x64 安装包用 `npm run dist:win`。Windows 包已在 macOS 上交叉构建，安装与运行仍需 Windows 实机验收。首次安装 Electron 需要下载运行文件；若环境禁止安装脚本，执行 `node node_modules/electron/install.js`。

Windows 分享文件为 `admin/release/犬影村管理平台 Setup 0.0.1.exe`，适用于常见 Intel/AMD 64 位电脑。接收人双击安装，可选择安装目录，完成后打开“犬影村管理平台”，联网并使用已绑定的用户名或管理员邮箱及密码登录。只需分享安装程序，不要分享 `.env`、源码或备份。当前安装包没有代码签名，Windows 可能提示未知发布者；不要关闭系统安全防护。Mac 与 Windows 管理的是同一个线上项目，安装程序不会创建管理员账号。

## 桌面外观（0.0.2）

Windows 移除默认 File/Edit 菜单，标题区采用与页面一致的暖白颜色，并保留系统原生最小化、最大化和关闭按钮。Mac 标题区融入页面，保留左上角原生红绿灯与系统编辑快捷键。顶部 52px 标题区支持拖动窗口；原生按钮仍由系统处理，没有新增访问文件或执行命令的客户端接口。

界面统一为暖白与墨绿色，更新登录页、侧边导航、首页和底部连接状态。首页从线上读取人员、认证、课程、用户资料数量，加载失败时显示提示，不使用演示数字。0.0.2 安装包位于 `admin/release/v0.0.2/`，旧版本安装包保留。

## 管理员用户名登录（0.0.1）

管理员可以有多个。账号与密码由 Supabase Authentication 管理，`admin_users.user_id` 负责授权，新增的 `username` 是唯一登录别名（3–32 位小写字母、数字、下划线，字母开头）。客户端自动忽略用户名大小写，邮箱登录保持可用。

执行第三份迁移 `supabase/migrations/202609140003_admin_username.sql`，再部署 `supabase/functions/admin-login/index.ts`。`supabase/config.toml` 为该登录入口配置 `verify_jwt = false`，因为登录时尚无用户会话；函数通过 Supabase Auth 验证密码，并检查管理员权限后才返回会话。服务端默认的 service_role 密钥只在函数内部使用，用户名与邮箱的对应关系不向匿名用户公开。

用户名是已有管理员账号的登录别名，不会创建第二个用户。密码不保存在本仓库或安装包。以后增加管理员，先在 Authentication 创建独立账号，再由数据库维护者插入：

```sql
insert into public.admin_users(user_id, username)
values ('替换为新用户UUID', '新的唯一用户名');
```

修改 `username` 不会修改密码；移除管理员表记录会取消管理权限。不要将密码填进此表。修改登录界面后必须使用 0.0.1 或更新安装包，0.0.0 仅支持邮箱登录。

## 导入规则

在“名单导入”中选择 `.xlsx`，查看预览，再确认新增。支持咨询师导师、咨询师、咨询师实习、辅导师、辅导师实习、科普师、好家长七张同名工作表。首行列名必须包含姓名、昵称、证书编号、初始认证年份、最近认证年份。按列名解析，不依赖列位置；忽略历史名单、学号对照表和空白行。

- 文件上限 10 MB、5000 条有效记录、每表最多 10000 行。读取文本/数字和富文本，拒绝公式及链接等不明确单元格；昵称数字保留为字符串。仅支持此新版格式，旧版四列表不会被误识别导入。
- 证书编号去首尾空白并统一大写。相同编号、相同内容只保留一条；同号内容冲突的所有行都排除。年份只保留年，空白及 `NA` 为未提供，不推测月份。
- 数据库按证书编号查重。已有编号的姓名、资格或年份不同会报告冲突，不覆盖资料或更新认证。未出现在新名单里的旧证书保留；旧新编号变化不会自动视为作废或替换。
- 证书尾部七位数用作人员匹配线索，必须同时姓名一致；姓名相同而尾段不同、尾段对应多个档案等情况报告冲突。它是当前名单的匹配规则，不是普遍可靠的身份证明。
- 新人员默认待发布，在“人员与认证”中维护照片、简介、二维码并开启公开展示。已有人员保持发布状态，新证书会归入该人的认证列表。好家长等认证不自动等同于对外服务讲师。
- 旧档案迁移时逐条保留，避免丢失人工资料。确认同一人后在人员页勾选两条合并。非空照片、简介、二维码、昵称或展示设置不同会拒绝合并；标签合并去重。旧分享链接通过别名继续定位到保留档案。
- 每次确认导入使用数据库事务。数据库错误时整批回滚；业务冲突行跳过并列出。超时不能当作失败已回滚：界面保存提交编号，点击“重试确认结果”或重开应用恢复同一提交，避免重复写入。
- 重新对比和重新导入都会再次检查当前数据库。预览后其他管理员的操作可能改变最终新增数量，以提交结果为准。

## 备份、权限与连接

每次确认导入前，事务内保存人员、认证与旧链接映射的快照，并记录操作者、文件 SHA-256、原始工作表/行号和结果。合并保存受影响资料快照。导入历史可下载快照和核对结果。快照只用于名单恢复，不含图片二进制、账号、课程等其他业务数据；请另做数据库与 Storage 离线备份。恢复应在核对后由维护人员按快照处理，界面不提供可能覆盖后续编辑的一键回滚。

只有 `admin_users` 中的认证账号能管理业务数据和上传图片。普通登录与匿名用户只能读取已发布人员、有效证书、已发布课程和机构展示内容。旧原始表只允许管理员读取；旧版兼容视图遵循新版人员及认证公开权限。Storage 的 images 桶仍是公开图片桶，停用人员不等于撤回已公开的图片地址；敏感材料不要上传至此桶。

应用启动会查询一次机构表，显示结果、最近成功时间并提供重试。请求有超时，不用管理密钥。此功能仅检查连接，不保证免费 Supabase 项目长期不暂停，也不会自动恢复已暂停项目。长期稳定服务应使用不会因低活跃度自动暂停的付费方案。

## 验证

`npm test` 包含合成名单解析和本地 PostgreSQL（PGlite）测试；本机存在私有名单时另执行真实名单回归测试。测试涵盖：权限隔离、查重、冲突、重复提交、事务回滚、合并与快照。`npm run build` 执行类型检查及生产构建。桌面界面测试使用模拟接口，不向线上写入。上线前还需用真实管理员账号完成导入验收，并在微信开发者工具/真机确认请求和图片下载域名配置、列表、详情及旧链接。

桌面界面自动验收：先构建，再在 `admin` 目录运行 `node tests/desktop.smoke.mjs`。它使用独立临时配置目录与模拟接口，验证连接检查、登录、文件预览、确认导入和退出，结束后删除测试登录数据。

本次已验证真实新版名单在空白本地测试库形成 45 份人员档案和 76 张证书，再次导入新增 0 条。线上随后已完成备份、迁移与合并：45 人、82 张证书（原有 39 张加新增 43 张），其中 20 人为待发布草稿；1 条姓名冲突保留原记录。

桌面发布包需要目标系统验收；公开分发 macOS 应用需使用自己的开发者身份签名与公证，Windows 同理配置代码签名。开发包不可称为已签名正式发行版。
